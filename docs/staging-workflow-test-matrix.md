# TEF Stock — Staging Workflow Test Matrix

เอกสารนี้ใช้ตรวจเว็บทดสอบก่อน Merge/Deploy เท่านั้น  
ห้ามใช้บัญชี Production และห้ามกดบันทึกรายการสต็อกจริงระหว่างการทดสอบ

## ขอบเขต

- เว็บทดสอบ: `tefthailand.github.io/tef-stock-staging/`
- กลุ่มผู้ใช้: Admin, TEF Staff (@tefthailand.com), Gmail/External
- เบราว์เซอร์หลัก: Google Chrome
- ขนาดจอ: desktop, 375 px, 320 px
- ภาษา: ไทย และ English

## กติกาข้อมูลทดสอบ

1. ใช้รายการตัวอย่างหรือรายการที่ผู้ดูแลเตรียมไว้ใน staging เท่านั้น
2. ห้ามสร้างคำขอที่มีผลต่อสต็อกจริง
3. ถ้าจำเป็นต้องทดสอบการบันทึก ให้ใช้ข้อมูลจำลองที่ระบุว่า TEST และตรวจ Undo/rollback หลังจบ
4. เก็บภาพหน้าจอเมื่อพบข้อผิดพลาด พร้อม URL, บัญชี/บทบาท, เวลา และรหัสรายการ
5. ผ่านการทดสอบแล้วต้องตรวจหน้าเว็บทดสอบใหม่อีกครั้งก่อน Merge

## Matrix

| ID | Flow | ขั้นตอนหลัก | ผลที่ต้องได้ |
|---|---|---|---|
| AUTH-01 | Admin | เข้าระบบแล้วเปิด Home | เห็นงาน Admin และเมนู Admin เท่านั้น |
| AUTH-02 | Staff | เข้าด้วย @tefthailand.com | ไม่เห็นเมนู/ปุ่ม Admin |
| AUTH-03 | Gmail | เข้าด้วย Gmail หรือ email code | เห็นเฉพาะเมนูของ External |
| LANG-01 | ภาษา | สลับไทย–English ที่ Home และทุกหน้าหลัก | ข้อความ UI เปลี่ยนครบ ไม่เหลือ label สำคัญเป็นภาษาไทย |
| BOR-01 | เบิก | ค้นหารหัส/ชื่อ เลือกรายการ ดูรูป ใส่จำนวน | รูปตรงกับรายการและจำนวนไม่เกินยอด |
| ISS-01 | จ่าย | Admin เปิดแท็บจ่าย เลือกรายการและดูรูป | Staff/Gmail ไม่เห็นแท็บจ่าย |
| RET-01 | คืน | เลือกเอกสาร/รายการคืน ดูรูปและจำนวนค้างคืน | ไม่แสดงรูปของรายการอื่น |
| MOV-01 | ย้าย | เลือกต้นทาง/ปลายทาง ดูรูป | รหัส ชื่อ รูป และสถานที่ตรงกัน |
| CNT-01 | ตรวจนับ | เลือกรายการ ดูรูป ใส่ยอดจำลอง | ส่วนต่างคำนวณถูกต้อง |
| IMG-01 | รูป | เปลี่ยน A → B ระหว่างรูปกำลังโหลด | รูปสุดท้ายต้องเป็นของ B เท่านั้น |
| UNDO-01 | Undo | Admin ย้อนรายการทดสอบ | แสดงข้อความสำเร็จและรีเฟรช/กลับไปสถานะใหม่ชัดเจน |
| HOME-01 | Home | กดการ์ดงาน Admin เมื่อไม่มีงานค้าง | ไปหน้าที่มีอยู่จริง ไม่ค้างที่ anchor ว่าง |
| UI-01 | Mobile | เปิดทุกหน้าที่ 320 และ 375 px | ไม่ล้นกรอบ ไม่มี horizontal scroll ที่ไม่จำเป็น |
| PRINT-01 | Print | พิมพ์ Borrow/Issue/Return/Transfer/Count | หัวกระดาษ โลโก้ ตำแหน่งสมาคม และรูปแบบเอกสารเป็นมาตรฐานเดียวกัน |

## Definition of Done

- ไม่มีข้อผิดพลาดระดับ blocker/critical
- รูปภาพไม่สลับรายการ
- สิทธิ์ผู้ใช้ไม่รั่วข้ามบทบาท
- สลับภาษาได้ครบในเส้นทางที่ทดสอบ
- เว็บมือถือไม่ล้นกรอบ
- Print Preview ผ่านทั้งไทยและอังกฤษ
- ไม่มีการบันทึกข้อมูล Production

## รายงานผล

บันทึกผลเป็น `PASS`, `FAIL`, หรือ `BLOCKED` ต่อ ID พร้อมหมายเหตุสั้น ๆ  
รายการที่ FAIL ต้องเปิด issue/PR แยกก่อนนำขึ้น Production
